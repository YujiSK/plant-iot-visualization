ただし、センサー値の解釈には2つの重要な注意があります。

1. 1号機`raspi`は現在バジル栽培キットへ設置されていません。水位ADC値が`2～3`程度で`dry`判定となり、vitalityは25ですが、これは未設置状態のセンサー入力を評価した結果です。植物の水不足を示す警報として扱ってはいけません。
2. `raspberrypi2`のBH1750は雨を避けるため青色蓋のタッパー内部にあります。現在の照度値は葉面照度ではなく、容器内部へ到達した光の参考値です。

現行コードはこの参考照度を日中のvitality計算へ含めています。そのため、透明ケースへ移設するまで、2号機のvitalityは水位・養液温度を中心に解釈し、照度による減点は暫定値として扱います。


## 4. ソフトウェアとデータの流れ

### 4.1 1号機

1. `send_sensor.py`が互換エントリーポイントとして起動する
2. 内部で`send_sensor_raspi.py`を実行する
3. DHT11、DS18B20、ADC CH0、ADC CH1を読み取る
4. `calculate_basil_vitality()`で環境ストレスを評価する
5. ローカルFastAPIへPOSTする
6. FastAPIがSQLiteへ保存する
7. 同じデータをSupabaseへPOSTする

### 4.2 2号機

1. `send_sensor_raspberrypi2.py`が起動する
2. DS18B20、BH1750、フロートスイッチを独立して読み取る
3. 一部センサーが失敗しても、取得できたセンサーの送信を継続する
4. `calculate_basil_vitality()`で評価する
5. Supabaseへ直接POSTする

### 4.3 送信周期

標準設定は`SENSOR_INTERVAL_SECONDS=300`です。

通常送信時刻は概ね次のように5分境界へ揃います。

```text
00分、05分、10分、15分、20分...
```

### 5.3 vitalityが25である理由

気温28.6℃と湿度44%だけを見ると、直ちに危険な状態ではありません。養液温度29.0℃は目標域より高く、注意域です。

しかし、最も大きな要因は水位ADCです。

現在の判定:

```text
raw < 200    -> dry
raw < 800    -> transition
raw < 1800   -> wet
raw >= 1800  -> enough_water
```

実測値は`2`であるため`dry`です。新しいvitalityロジックは、水位低下を他の良好値で相殺しません。

```text
water_status = dry
-> vitality上限 = 25
```

したがって、旧ロジックのvitality 82から、新ロジック適用後は25になりました。

ただし、1号機は未設置です。この25点は「未設置状態の水位入力を新ロジックが正しく重く評価した」という技術確認値であり、植物の健康度ではありません。

### 5.4 水位ADCについての注意

現在は栽培キット自体へ設置されていないため、この値から植物の水不足を判断することはできません。

未設置状態で低値になる理由:

- 水位センサーが水に触れていない
- 動作確認用の開放状態になっている
- 3.3V駆動では出力変化が小さい
- 腐食、濡れ面積、配線、ADC入力の影響

将来1号機を栽培キットへ設置する場合は、次の順番で校正します。

1. 空中でのADC値を記録する
2. センサーを水へ浸したときのADC値を記録する
3. 実際の設置深さで値を確認する
4. `dry`、`transition`、`wet`、`enough_water`の閾値を現物に合わせる
5. フェルトや根への給水状態とADC値を対応付ける

### 6.3 養液温度の解釈

28.0℃は許容域の上端です。

現在の評価帯:

| 養液温度 | 評価 |
|---|---|
| 22～26℃ | 目標域 |
| 18～28℃ | 許容域 |
| 15～18℃未満、28～30℃未満 | 注意域 |
| 30℃以上 | 強い注意 |

屋外設置では、日射によって容器と養液が温まりやすくなります。養液温度が30℃以上になると、根の呼吸需要が増える一方、水中の溶存酸素が減りやすくなるため、根域ストレスを重く評価します。

現在の28.0℃は直ちに危険ではありませんが、昼以降にさらに上昇するかを監視する必要があります。

### 6.4 フロートスイッチの解釈

現在のコードでは次の対応です。

```text
GPIO17 LOW  -> triggered=True  -> low_water
GPIO17 HIGH -> triggered=False -> water_ok
```

最新値は`water_ok`です。

ただし、フロートスイッチは浮きの上下方向を反転すると接点の意味も反転します。現在の設置方向で、本当に「水が減ったときにLOW」になるかを現物で最終確認する必要があります。

## 7. BH1750照度の現在の扱い

### 7.1 現在の設置

BH1750は屋外の雨から守るため、青色の蓋が付いたタッパー内部に設置されています。

この配置には次の影響があります。

- 青色蓋が光を遮る
- 特定波長が選択的に通過・遮断される
- センサーが葉と異なる位置の光を測る
- タッパー内部の反射や影響を受ける
- 葉が実際に受ける光より低く表示される可能性が高い

したがって、現在の`light_lux`は次の意味で扱います。

```text
葉面照度ではない
容器内部へ到達した光の参考値
時間変化を観察するためのログ
```

### 7.2 記録を続ける理由

値が葉面照度として正確でなくても、記録自体には意味があります。

- 晴天、曇天、雨天の変化を比較できる
- 朝から昼への相対変化を確認できる
- 透明ケース移設前後の差を比較できる
- センサー故障や配線断を検知できる

ただし、現在の低い値だけを根拠に「バジルが光不足」と断定してはいけません。

### 7.3 透明防水ケースへの移設

今後の設置目標:

- 青色蓋の内側から外へ出す
- 透明な防水ケースへ収納する
- 葉と同程度の高さへ設置する
- BH1750の受光面を上向きにする
- 葉、容器、壁の影を避ける
- ケーブル出口を防水する
- ケース内部の結露対策を行う
- 透明窓の汚れを定期的に清掃する

### 7.4 透明ケース移設後の校正

透明ケースにも透過損失があります。

同じ場所・同じ時間帯・同じ天候で、ケースなしとケースありの値を比較します。

```text
補正係数 = ケースなし照度 / ケースあり照度
補正照度 = ケースあり測定値 x 補正係数
```

1回だけでは天候変動の影響が大きいため、晴天・曇天・朝・昼など複数条件で比較するのが望ましいです。

## 8. light_statusとvitality照度評価の違い

現在、2つの閾値が存在します。

### 表示用`light_status`

```text
100 lx未満   -> dark
1000 lx未満  -> dim
1000 lx以上  -> bright
```

### vitality用照度評価

```text
10000 lx以上 -> 100点
5000 lx以上  -> 80点
2000 lx以上  -> 60点
500 lx以上   -> 35点
500 lx未満   -> 15点
```

このため、例えば1622.5 lxは次のようになります。

```text
light_status: bright
vitality: 日中照度が低い
```

これはセンサー故障ではなく、表示ラベルと栽培評価の基準が異なるためです。

さらに、現在のBH1750は青色蓋内部にあるため、この矛盾を解消する閾値調整は透明ケース移設後に行う方が合理的です。

## 9. vitality評価ロジック

### 9.1 基本思想

旧ロジックは、主に気温と湿度の加重平均でした。この方式では、水位が危険でも他の値が良好なら高得点になる可能性がありました。

新ロジックでは次の2段階で評価します。

1. 各センサーを重み付きで評価する
2. 緊急条件に応じてスコア上限を適用する

### 9.2 基本重み

| 項目 | 重み |
|---|---:|
| 水位 | 35 |
| 養液温度 | 30 |
| 気温 | 20 |
| 日中照度 | 15 |
| 湿度 | 10 |

センサーが存在しない機体では、取得できた項目だけで重みを正規化します。

### 9.3 緊急上限

| 条件 | vitality上限 |
|---|---:|
| 水位低下・dry | 25 |
| 養液30℃以上 | 55 |
| 養液15℃未満 | 40 |
| 水位低下 + 養液温度異常 | 15 |
| 養液30℃以上 + 日中10,000 lx以上 | 45 |
| 水位情報を取得できない | 70 |

### 9.4 照度評価時間

瞬時照度は夜間に低くて当然です。そのため、照度はローカル時刻の09:00～15:00のみvitalityへ反映します。

この時間外でも照度値自体はSupabaseへ記録します。

## 14. 現在のリスクと優先順位

### 優先度A: 現物確認が必要

#### 2号機のフロート方向

現在は`water_ok`ですが、最終設置方向でLOWが本当に水不足を意味するか確認が必要です。

### 優先度B: センサー設置改善

#### BH1750の透明防水ケース移設

青色蓋内部では葉面照度を測れません。透明ケースへ移し、葉と同程度の高さへ設置します。

### 優先度C: ソフトウェア整合

#### 1号機未設置データの表示

1号機のセンサー送信は技術確認として継続していますが、未設置値が通常の栽培データと同じ形式で表示されます。将来的には、未設置・試験中・本番設置を識別する運用状態を持たせると誤解を防げます。

#### light_status閾値

`bright >= 1000 lx`という表示閾値と、vitalityの栽培評価閾値が一致していません。透明ケース移設後の実測データを基に統一します。

#### 1号機service名

1号機は旧名`plant-sensor.service`を使用しています。内部動作には問題ありませんが、将来的には`plant-sensor-raspi.service`へ整理すると2台構成が分かりやすくなります。

### 優先度D: 機能追加

- 給水、植え替え、養液交換を`care_logs`へ記録するUI
- 日中積算luxの算出
- 通知機能
- pH、EC、溶存酸素の追加
- 長期データとcare logを使った回復傾向分析

## 16. 運用上の判断基準

### すぐ確認する条件

- `float_switch_state=low_water`
- 設置中の機体で`water_status=dry`
- 養液温度30℃以上
- 養液温度15℃未満
- センサー値が突然NULLになる
- Supabase送信が201以外になる
- serviceがinactiveまたはfailedになる

### 経過観察する条件

- 養液温度28～30℃未満
- 青色蓋内部の照度が低い
- 一時的な照度変動
- 曇天や雨天による照度低下

### センサー値だけで断定しない条件

- BH1750の瞬時lux
- 未設置の1号機から取得した全センサー値
- vitality単独の点数

植物の葉のしおれ、黄化、根の色、臭い、保持材の湿り、実際のタンク水位と合わせて判断します。
