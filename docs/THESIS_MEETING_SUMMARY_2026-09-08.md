## 1. これまでの研究経緯と現在の方向

本研究では当初から、フェルト等を用いた毛細管現象による受動給水を植物管理システムへ取り入れてきました。初期には簡易的な吸水・給水測定を行い、その後はRaspberry Piを中心としたIoT監視システムの構築・連続運用に重点を置いてきました。

現在までに、養液温度・照度・水位状態の取得、Supabaseへのログ蓄積、Web可視化、通知機能、補助指標としてのVitality Score算出などを実装しています。

一方、毛細管給水方式そのものについては、比較条件・反復数・評価指標を揃えた定量評価が十分ではありません。そこで、**研究テーマを変更するのではなく、当初から扱ってきた毛細管給水を中心的な評価対象とし、その定量評価を補完した上で、既存のIoTセンシングを給水状態の観測・補助評価に用いる方向**を検討しています。

研究質問案は、以下のように考えています。

- **中心的な研究質問:** 毛細管現象を利用した受動給水は、小規模な植物管理において、どのような条件でどの程度安定して給水できるか。
- **IoTセンシングに関する研究質問:** その給水状態や給水経路の異常を、既存のIoTセンシングによってどこまで把握できるか。

異常事象直前までの区間（2026-07-22 13:05 ～ 2026-08-02 19:15 JST、約5分周期）を解析しました。

|---|---:|
| 期待観測枠 | 3,243 |
| 対応観測枠 | 3,240 |
| 欠測枠 | 3 |

| 欠測率 | **0.09%** |
| 平均時刻ずれ | **0.600秒** |

この99.91%は、毛細管給水性能やセンサ値の精度ではなく、**データ取得・記録をほぼ継続できたことを示す結果**として位置づけています。

### 連続運用中の異常事象

2026-08-04に、栽培装置の転倒、植物の著しい萎凋・枯死、電源コードの抜けが確認されました。ログ上では8月2日19:16頃に、水位状態、照度、Vitality Score、温度値などが急変し、その後約39時間観測が途絶しています。

この時刻に何らかの装置・センサ系異常が発生した可能性は高いと考えていますが、転倒時刻や原因は断定していません。卒業研究では中心テーマではなく、必要に応じて補助的な異常事例として扱う想定です。

## 3. 現在不足している評価

現在のIoTシステムでは、貯水部の水位や周辺環境は把握できますが、以下は十分に評価できていません。

- 毛細管給水による給水量・給水速度
- 給水の時間的安定性や反復間のばらつき
- 条件差による給水性能の変化
- 実際に植物側・根域まで水が到達しているか
- 給水経路の異常をIoTでどこまで把握できるか

特に、

> 貯水部に水がある
> → 毛細管材が水を輸送する
> → 根域へ水が到達する

という各段階を、現在は直接区別して計測できていません。この観測上のギャップを、追加実験と補助計測でどこまで埋めるかを検討したいと考えています。

## 4. 10月6日までの追加評価案

### A. 毛細管給水の基礎評価

まずは多数の条件を同時に変えず、**1つの主要因のみを変える**実験を想定しています。

- 給水材は実機で使用しているフェルトに固定
- 材質・幅・厚さ・浸漬長などは可能な限り固定
- 高さ差など1要因を少数条件で比較
- 給水量・給水速度・時間変化を測定
- 反復を行い、ばらつき・再現性を確認
- 給水材なしの対照で蒸発影響を見積もる
- 可能であれば受け側への到達水量も測定

最終的な独立変数、条件数、反復数、「安定性」の評価指標は、打ち合わせ内容を踏まえて確定したいと考えています。

### B. 実植物での短期予備評価

基礎評価後、実植物で数日程度運用し、正常条件と、給水材の接触不良・給水経路断絶など安全に再現可能な少数の異常条件を比較することを想定しています。IoTログに加え、必要に応じて重量変化等の補助計測も併用します。

10月6日までには、全ての本評価を終えるのではなく、**研究質問と評価方法を固め、予備的に「実験 → 解析 → 考察」まで一度通す**ことを目標として考えています。
