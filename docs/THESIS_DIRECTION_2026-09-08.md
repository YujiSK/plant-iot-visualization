# 卒業研究 方向性整理 v1.0

更新日: 2026-09-08
研究室内発表: **2026-10-06**

## 1. 研究の再定義

本研究では、毛細管現象を利用した受動給水機構とIoTセンシングを組み合わせ、室内・小規模環境における植物管理支援システムとしての有効性を検討する。

従来は植物状態の可視化、IoTセンシング、通知・ログ収集機構の構築が中心となっていたが、今後は「毛細管現象による給水」と「IoTによる観測・異常検知」を一体の研究課題として扱う。

仮タイトル:

> 毛細管現象を利用した受動給水機構とIoTセンシングによる植物管理システムの検討

## 2. 主たる研究質問

本研究の主たる問いを以下とする。

> 毛細管現象を利用した受動給水機構は、植物に対してどの程度安定して水分を供給でき、その状態変化や異常をIoTセンシングによってどこまで観測・検知できるか。

補助的な問い:

1. 毛細管給水材は、距離・水位差・時間等の条件によってどの程度の給水性能を示すか。
2. 正常な毛細管給水状態では、水位・温度・照度・Vitality Score等はどのような傾向を示すか。
3. 給水経路の異常、水不足、装置転倒等の異常時に、既存センサ値からどの程度異常兆候を把握できるか。
4. 現行IoTシステムでは検知できない物理異常は何か。また、どのような追加センサ・監視方法が必要か。

## 3. 研究上の構成

本研究では以下の2層を明確に分ける。

### 3.1 物理層: 毛細管現象による受動給水

- 貯水部
- フェルト / 吸水布 / 綿紐等の毛細管給水材
- 植物保持部
- ポンプを常時使用しない低メンテナンス構成

評価対象:

- 吸水量
- 給水速度
- 水位差
- 給水距離
- 給水継続時間
- 給水破綻条件

### 3.2 情報層: IoTセンシング・可視化・異常検知

既存構成を活用する。

- Raspberry Pi
- DS18B20: 養液温度
- BH1750: 照度
- フロートスイッチ: 水位状態
- Vitality Score
- Supabase `sensor_logs`
- GitHub Pagesによる可視化
- LINE / Slack通知
- 画像・AI観察機構

IoT部分は、毛細管給水機構の状態を観測・評価するための計測基盤として位置付ける。

## 4. 既存成果の位置付け

### 4.1 通常運転性能評価

事故前評価区間を以下で固定済み。

- 開始: 2026-07-22 13:05 JST
- 終了: 2026-08-02 19:15 JST
- 対象: `raspberrypi2` / `location-b`

5分周期正規化評価結果:

- 期待観測枠: 3,243
- 対応観測枠: 3,240
- 欠測枠: 3
- Coverage: **99.91%**
- 欠測率: **0.09%**
- 期待時刻からの平均ずれ: 0.600秒

この結果は、事故前におけるIoT計測・送信系の高い安定性を示す基礎評価として使用する。

### 4.2 センサ分布

事故前正規化区間では以下が確認されている。

- 養液温度平均: 33.06 ℃
- 30 ℃以上: 87.8%
- 35 ℃以上: 28.5%
- `low_water`: 0件
- Vitality Score平均: 58.08
- Vitality Score 50–69: 83.1%

事故前から高温ストレスが存在していたため、事故前区間を「植物にとって理想的な生育環境」とは扱わない。

### 4.3 2026-08-02 急性イベント

2026-08-02 19:16:39 JSTに以下の急激な状態遷移が観測された。

- DS18B20: 85.0 ℃（エラー様値）
- 照度: 約2,800.8 lx
- `low_water`
- `float_switch_triggered = true`
- Vitality Score: 5

その後Supabase観測は約39時間途絶し、2026-08-04に装置が転倒・植物が著しく萎凋した状態で発見された。

現段階では「8月2日に転倒した」「強風が転倒原因だった」「同時刻に電源コードが抜けた」といった因果関係は断定しない。

本研究ではこの事故を、単なる失敗ではなく、

> IoT計測系が安定稼働していても、給水経路や装置姿勢等の物理異常を十分には検知できない

というシステム限界を示すケーススタディとして扱う。

## 5. 今後追加する実験

大規模な栽培実験を新規に開始するのではなく、卒論として必要な最小限の追加評価を行う。

### 実験A: 毛細管給水材の基礎特性評価

目的:
毛細管現象による給水性能を定量化する。

候補条件:

- 給水材: フェルト等
- 給水距離
- 高低差
- 水位条件
- 測定時間

測定項目:

- 吸水前重量
- 吸水後重量
- 経過時間
- 吸水量
- 給水到達距離

過去に取得したフェルト浸漬重量等のデータは予備実験として再利用可否を確認する。

### 実験B: 実植物・実装置での短期連続運用

目的:
毛細管給水とIoTセンシングを実際に組み合わせ、数日程度の連続運用を評価する。

測定候補:

- 水位
- 養液温度
- 照度
- Vitality Score
- 給水状態
- 植物外観
- 補水回数

### 実験C: 異常状態評価

安全に再現可能な範囲で、異常状態を意図的に発生させ、現行センサでどこまで検知可能か確認する。

候補:

- 給水材が水に接触しなくなる
- 給水経路が外れる
- 貯水量が低下する
- センサ値が欠測する

※ 植物を意図的に枯死させることを目的としない。

## 6. 評価指標

### IoTシステム側

- データ取得率
- 欠測率
- 観測周期ずれ
- 異常検知可否
- 通知到達可否
- センサ値変化量

### 毛細管給水側

- 単位時間あたり吸水量
- 給水可能距離
- 給水継続時間
- 水位差に対する給水性能
- 給水破綻条件

### 統合評価

- 毛細管給水状態とセンサ値の対応関係
- 給水異常発生から検知までの時間
- IoTのみでは観測できない物理異常
- 低メンテナンス植物管理としての実用上の制約

## 9. 現時点の研究上の主張（暫定）

現時点では以下を最終結論として断定せず、今後の実験で検証する。

暫定仮説:

> 毛細管現象を用いた受動給水は、ポンプ等を用いない低メンテナンス植物管理に適する可能性がある。一方、安定運用には給水経路そのものの物理状態の把握が必要であり、温度・照度・水位等の一般的なIoTセンシングだけでは一部の異常を直接検出できない。したがって、受動給水機構とIoT監視を統合し、物理層と情報層の双方から管理する設計が重要である。
